Agentic development

Specs in, reviewed code out

This is the part of my work I'm most passionate about: using AI agents to build and customize Odoo faster, with specs and review keeping the output trustworthy.

  1. Write the spec firstGoal, constraints, access rules and acceptance checks come before any code, so the work has a clear definition of done.
  2. Give the agent real contextOdoo version, module layout, conventions and what must not be touched, kept in instruction files the agent reads every time.
  3. Direct, then reviewThe agent builds in small steps. I review the diffs and run the tests before anything is merged.
  4. Train from failuresWhen an agent gets something wrong, I fix its instructions and examples, not only the output, so the next run starts better.
specs/sale-approval-limit.mdillustrative example
# Spec: Sales order approval limit

## Goal
Orders above a configurable amount need
manager approval before they can be confirmed.

## Constraints
- Odoo 18, new module, no core overrides
- Limit is set per company in Settings
- Only the Sales Manager group can approve

## Acceptance
[ ] Confirm is blocked above the limit
[ ] Approval unlocks the order and is logged
[ ] Tests cover below, at and above the limit

Anatomy of a protected API callA composite of controls I built across my projects
  1. 01 · RequestClient callMobile app or integrator hits a documented REST endpoint.
  2. 02 · AuthenticateJWT + OTPToken auth with one-time codes and phone-number login.
  3. 03 · AuthorizeAccess rulesGroup permissions and per-tenant record isolation.
  4. 04 · ExecuteSafe transactionControllers roll back fully if any validation fails.
  5. 05 · RecordAudit trailActions logged with IP address, including downloads.
